# Surf 群组邀请流程改进 — 2026-10-28

## 发现与处理

1. 已注册用户被邀请会直接加入，收件人没有选择。Surf 现在发送 require_confirmation=true：生成收件人绑定的待确认邀请，不直接写成员关系。旧客户端批量导入行为保留。
2. 发送接口按收件人返回结果，客户端却统一提示成功。Web/小程序现在保留对话框、逐项展示成功/失败/已是成员；输入去空白、去重并支持中文分隔符，后端拒绝空列表及超过 50 人。
3. 通知只有动作字符串，没有接受入口。新增收件人待确认邀请列表与接受/拒绝操作；群组页面识别已有邀请，显示“接受邀请并加入”，无邀请时明确“申请加入/等待审核”。
4. 邮件地址为 /group/join/:name?invite=:id，Surf 没有对应页面。新增兼容落地页及 /invite/:id；登录前保留目的地，登录/注册成功后返回。身份不匹配、过期/撤销给出反馈。
5. 重复邀请会重复发邮件。复用同群组尚有效的待确认邀请；电子邮件按登录规则规范化。未知手机号在 Surf 确认模式下不生成自动接受的白名单。
6. 可复用邀请码未检查撤销状态，且低级别邀请码可覆盖已有高级角色。修复状态校验并保留更高级成员身份。

## 用户流程

管理员在群组关于页/邀请成员输入用户名或邮箱 → 逐项查看发送结果 → 对方登录后进入“我的 → 通知”或打开邮件邀请链接 → 先查看群组、接受或拒绝 → 接受后进入群组，成员列表/日历使用新关系。仅打开邀请不加入，拒绝也不加入。

旧版已直接添加的成员不会被移除。修改后的小程序需重新上传；旧版客户端不传确认参数，继续原有行为。
