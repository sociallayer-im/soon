# 活动标签、库存和位置接口

- `GET /api/v1/events/tag_suggestions?q=摄影&limit=10` 从可公开发现的已发布活动中返回文本标签，按出现次数降序、标签升序排列；最多 20 条，不暴露草稿和仅链接访问活动。旧的 `tags` 数组不变。
- `GET /api/v1/events?tag=摄影` 精确匹配单个标签，并沿用现有活动可见性和浏览范围规则。原 `tags` 过滤维持兼容。标签精确筛选使用 GIN 索引；建议查询展开公开活动的文本数组，数据量增长后应监控并考虑维护聚合表。
- `PATCH /api/v1/events/:event_id/tickets/:ticket_id` 支持 `ticket.total_quantity`，表示总票数，空值表示无限量。现有 `quantity` 仍表示剩余量，不能同时传入两者。仅活动管理员可修改；总数不能小于未释放的已售和预留数量，待审核且尚未占库存的订单不计入。活动锁与票种锁用于与报名操作同步。
- 报名时活动总名额、场地容量和各票种余量分别检查；待付款占位、取消与超时释放由现有报名状态机处理。
- 群组详情返回 `latitude`、`longitude`，允许群组管理员在更新群组时成对设置或清空。场地和活动自定义地点通过 Places 接口保存坐标。
- 评论和活动讨论按 `created_at DESC, id DESC` 排序后分页，确保相同时间下顺序稳定。当前为偏移分页，分页过程中有新记录插入或记录删除时仍可能出现跨页重复或遗漏；需要严格一致的跨页快照时应改为游标分页。
